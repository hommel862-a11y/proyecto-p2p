# CRM / ARM Liquid Glass Redesign, Unified Botonera & PostgreSQL Hardening — P2P Decisor
Objective: Evolucionar `ComplianceCockpitComponent` y la persistencia CRM/ARM hacia una arquitectura modular de 5 apartados unificados (`Overview`, `Pipeline`, `Inbox & Studio`, `Contacts & Rails`, `Audit & System`) bajo estética Spatial Liquid Glass / Apple Pro OLED Midnight con compatibilidad total en los 4 temas (`dark`, `apple-dark`, `light`, `neon-pink`), botonera jerárquica sin duplicaciones, unificación de los 3 silos (`ARM_B2B`, `P2P_DESK`, `FINANCE_360`) sin mocks estáticos y endurecimiento productivo PostgreSQL + `pgvector` en VPS + espejo Electron SQLite.
Branch: `feat/p2p-decision-tool-mvp` | Delivery strategy: `exception-ok` (work-unit commits en `feat/p2p-decision-tool-mvp`, forecast ~2,400 líneas entre frontend modular, SQLite/IPC, gateway y PostgreSQL; push/PR quedan bajo decisión del usuario) | Test runner: `npx ng test p2p --watch=false --include=...`, `npm run inbound:test`, `npm run inbound:typecheck`, `npm run test:electron`, `npm run mcp:test`, `npm run check:vendor`, `npm run typecheck`, `npm run lint`, `npm run build`

## Specs
- **S1 — Dashboard de Alto Nivel y Rediseño Visual Glassmorphism (Referencias 1, 2 y 3 + 4 Temas):** "Quiero que en el área del CRM le hagas un dashboard de alto nivel y le cambies todo el sistema de su interfaz" / "busca la manera de integrar un mejor dashboard de este busca la manera de que a esa interfaz tenga glassmorphism de alto nivel." / "toma como referencia las imagenes y haz un plan dame las imagenes de como va a quedar el CMR toda la herramienta completa cada uno de sus apartados dame las mejores recomendaciones"
  - Aprobado en `PROPUESTA_CRM_ARM_GLASSMORPHISM_PSQL.md`: Separación estricta Liquid Glass (capa funcional flotante: barra de comandos superior, cápsula de 5 pills, inspector flotante HITL, paleta `⌘K` y barra/sheet móvil con fallback `@media (prefers-reduced-transparency: reduce)` / `prefers-contrast: more` / `prefers-reduced-motion: reduce`) vs. materiales elevados de contenido (`--panel`, `--panel-2`, `--line`, `--line-strong`, `--text`, `--muted`).
  - Apartado 1 (`Overview`): 4 KPIs con aura radial localizada, `Cashflow & Treasury Spectrum` (5 columnas + barra segmentada + `AI Strategist` embebido), `Deal Type & Velocity` (barras proporcionales + selector de periodo), `AI Health Score` con recomendaciones accionables en 1 clic, y tabla `Deals Status` con divisores hairline.
  - Eliminar todos los colores hex hardcodeados en Vistas 1–7 y modales para compatibilidad completa en `dark`, `apple-dark`, `light` y `neon-pink`, y descomponer `ComplianceCockpitComponent` en subcomponentes modulares manteniendo cada SCSS `< 120 kB` (`angular.json` `anyComponentStyle`).
- **S2 — Reorganización de la Botonera, 5 Apartados Unificados y Responsividad Móvil:** "y organicemos todo lo que son el tema de la botonera, los botones"
  - Consolidar las 8 pestañas con emojis (`DASHBOARD`, `KANBAN`, `CONTACTS`, `BANKS`, `ACTIVITIES`, `OMNICHANNEL`, `ARM_COMMAND`, `SETTINGS`) en 5 pills vectoriales monocromas (`Overview`, `Pipeline`, `Inbox & Studio`, `Contacts & Rails`, `Audit & System`) preservando compatibilidad de `setView()` / `activeView()` para contratos y pruebas existentes.
  - Eliminar botones duplicados (`+ Nuevo Trato` 3x, `+ Contacto` 2x, `+ Banco` 2x, `activeScope` 2x, Verificador 2x): máximo 1 CTA primario `+ Nuevo ▾` en la cabecera derecha, `Search ⌘K`, `Gateway`, y menú `⋯` (`Privacidad Alt+P`, `Corte #SETTLE` en `P2P_DESK`); máximo 2 acciones por tarjeta Kanban + menú contextual `⋯`.
  - Resolver colisión `Ctrl+K` / `⌘K` entre `HotkeysService` y `ComplianceCockpitComponent` (paleta unificada con scope CRM sin disparar ambas superpuestas).
  - Añadir breakpoints responsivos (`<= 768px`, objetivos táctiles `>= 44×44px`) en `Inbox & Studio`, `Contacts & Rails` (`Expediente 360°`) y listas Kanban/Overview para web móvil y Capacitor Android.
- **S3 — Unificación de 3 Silos (`ARM_B2B`, `P2P_DESK`, `FINANCE_360`) y Datos Reales sin Mocks Estáticos:**
  - Sincronización bidireccional entre `activeScope` y `activeArmSilo` bajo un selector único de 3 silos (`ARM B2B`, `Mesa P2P`, `Finanzas 360`), evitando desincronización de `setScope()`.
  - Reemplazar los números estáticos de `armExecutiveKpisForSilo()` por cálculo dinámico derivado de `armKanbanCardsForSilo()`, `deals()`, `armApprovalQueueForSilo()` y `armAutonomousFeedForSilo()`, preservando las métricas clave por silo (`MRR` en `ARM_B2B`, volumen USDT en `P2P_DESK`, pipeline en `FINANCE_360`), e hidratar `arm_leads` reales desde SQLite (`window.electron.arm.listLeads`) / `InboundGatewayService`.
- **S4 — PostgreSQL (`PSQL`) + `pgvector` Productivo, Endurecimiento Multi-Silo y Sincronización Híbrida:** "poder implementar una UI, una buena PSQL y organizar todo lo que es la interfaz de alto nivel para ese CMR"
  - Nueva migración `electron/main/db/migrations/002_crm_unification_and_hardening.sql`: tablas `bank_rails`, `payment_receipts` (`UNIQUE (workspace_id, bank_rail_id, reference_code)` anti-replay atómico), `treasury_settlements` (`idempotency_key` único), `billing_documents` unificado, `shadow_examples` (`VECTOR(768)` + HNSW), `ai_cost_ledger`; añadir `workspace_id` a `contacts` + activar `ENABLE`/`FORCE ROW LEVEL SECURITY` (`workspace_silo_isolation`) en todas las tablas multi-silo; precisión `NUMERIC(18, 6)` en montos/tasas; `version` + triggers `set_updated_at()`; índices parciales y cubrientes; trigger `pg_notify('arm_outbox_channel', ...)` sobre `outbox_events`.
  - Infraestructura VPS y Gateway (`deploy/vps/docker-compose.yml`, `.env.example`, `README.md`, `packages/inbound-gateway`): añadir servicio `postgres` (`pgvector/pgvector:pg17-alpine`) con healthcheck y migraciones montadas, e implementar `PgArmStore` (`pg` pool + `withWorkspaceTx` RLS + `LISTEN/NOTIFY` -> SSE + verificación anti-replay de referencias) con fallback limpio a memoria si `DATABASE_URL` no está definido.
  - Extensión local-first Electron SQLite (`electron/main/db/schema.sql`, `database.ts`, `arm.repository.ts`, `ipc/handlers.ts`, `preload/api.ts`, `shared/types.ts`) y `InboundGatewayService`: espejo local de `arm_bank_rails`, `arm_payment_receipts` (dedup atómico) y `arm_treasury_settlements` + endpoints cliente de almacenamiento y verificación de referencias.
- **S5 — Preservación de Contratos, Calidad y Presupuestos de Compilación:**
  - Mantener 100% verdes las suites existentes (`27/27` `compliance-cockpit.component.spec.ts`, `inbound:test`, `test:electron`, `mcp:test`, `check:vendor`, `typecheck`, `lint`, `ng build` con `anyComponentStyle < 120 kB`), más verificación visual en vivo Desktop (`1440×900`) y Móvil (`390×844`) en los 4 temas y auditoría final de verificador independiente.
